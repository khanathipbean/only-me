# Test Runs — Plan (เฟส 1)

Goal: หยิบ Test Case เดิมมาทดสอบซ้ำได้เป็น "รอบ" และ**เก็บผลของแต่ละรอบไว้**
เพื่อให้เปลี่ยน Sprint แล้วยังย้อนดูผลของ Sprint ก่อนได้

Current vs desired (Diff):
- now: `TestCase.testResult` เป็นฟิลด์เดียวค่าเดียว บันทึกผลทับของเดิมเสมอ
  ไม่มีตาราง Run/Cycle ในระบบ → รันซ้ำรอบใหม่ = ผลรอบก่อนหายถาวร
- want: `TestRun` เป็นรอบการทดสอบ (ชื่อ / ช่วงวันที่ / เปิด-ปิด) และ
  `TestRunCase` เก็บผลของเคสนั้น **ในรอบนั้น** พร้อมคนรันและเวลา

Out of scope / do NOT touch (Fence):
- **Dashboard** — ยังอ่าน `TestCase.testResult` เหมือนเดิม ไม่แยกตามรอบใน
  เฟสนี้ (45 จุดใน 8 ไฟล์ที่ใช้ฟิลด์นี้จึงไม่ต้องรื้อ)
- โครง Module / Requirement / Scenario / Test Group / Test Case — ไม่เปลี่ยน
- CSV import — ไม่ยุ่งกับรอบ
- Assignee — ยังปิดอยู่ตาม `ASSIGNEE_ENABLED`
- Attachment / TestStep — ผูกกับ Test Case เหมือนเดิม ไม่ผูกกับรอบ

Risks & unknowns:
- **ความจริงสองที่**: `TestCase.testResult` จะกลายเป็น "ผลล่าสุด" ที่ได้จาก
  รอบ ถ้าเขียนสองทางเมื่อไหร่ตัวเลขจะเพี้ยนทันที → ต้องบังคับให้เขียนผ่าน
  ฟังก์ชันเดียว และปิดทางเขียนตรงที่มีอยู่เดิม
- **รอบที่ปิดแล้วต้องเขียนไม่ได้** ไม่งั้นประวัติที่เก็บมาก็ไม่น่าเชื่อถือ
- **เพิ่มเคสเข้ารอบทีละ 129 แถว** ถ้าเขียนทีละแถวจะเจอปัญหาเดียวกับ import
  ที่ 504 บน Netlify (10 วินาที/60 วินาที) → ต้องใช้ `createMany` ตั้งแต่แรก
- เคสที่ถูก archive ทีหลัง: แถวในรอบเก่าต้องอยู่ต่อ (เป็นประวัติ) แต่ต้อง
  แสดงให้รู้ว่าเคสต้นทางถูก archive ไปแล้ว
- Netlify: หน้ารันต้องไม่ยิง query ต่อเคส

## การตัดสินใจที่ตกลงแล้ว

1. **สายกลาง** — เฟสนี้เก็บประวัติให้ได้ก่อน Dashboard แยกตามรอบทำทีหลัง
2. **รอบเก็บ ชื่อ + ช่วงวันที่ + สถานะ Open/Closed** ปิดแล้วแก้ผลไม่ได้
3. **ยกผลเดิมเข้ารอบ "Baseline"** ต่อโปรเจกต์ ประวัติจะได้ไม่ขาดตอน
4. `TestCase.testResult` = ผลล่าสุด sync จากรอบ (ไม่เลิกใช้ เพื่อไม่ต้องรื้อ
   Dashboard และลิสต์ทั้งหมดในรอบเดียว)

## Steps

1. **schema** — `model TestRun` (projectId, name, startsOn?, endsOn?, status,
   closedAt?, createdById, deletedAt?) + `model TestRunCase` (testRunId,
   testCaseId, testResult, notes?, ranById?, ranAt?) + `enum TestRunStatus`
   + `@@unique([projectId, name])` และ `@@unique([testRunId, testCaseId])`
   verify: `db push` ผ่าน (ขอความยินยอมก่อน) ข้อมูลเดิมครบ

2. **สคริปต์ backfill** — สร้างรอบ "Baseline" ต่อโปรเจกต์ ยกทุก Test Case
   ที่ยังไม่ถูกลบเข้าไปพร้อมผลปัจจุบัน แล้วปิดรอบ
   verify: จำนวนแถวใน `TestRunCase` = จำนวน test case ที่ live, รันซ้ำได้
   โดยไม่สร้างซ้ำ

3. **`src/lib/test-runs.ts`** — `listRunsForProject(Page)`, `createRun`,
   `updateRun`, `closeRun`/`reopenRun`, `addCasesToRun` (createMany เป็นชุด),
   `removeCaseFromRun`, `setRunCaseResult` (เขียน `TestRunCase` แล้ว sync
   `TestCase.testResult` ในทรานแซกชันเดียว + เขียน AuditLog)
   verify: ปิดรอบแล้วเขียนผลถูกปฏิเสธ; ผลล่าสุดของ Test Case ตรงกับรอบล่าสุด

4. **หน้า `/projects/[id]/runs`** — ลิสต์รอบ (ชื่อ ช่วงวันที่ สถานะ ความคืบหน้า
   x/y) + สร้างรอบใหม่ + แท็บ `Test Runs` ใน `ProjectTabs`
   verify: สร้าง/แก้/ปิด/เปิดรอบจริงแล้วเช็ค DB

5. **หน้า `/projects/[id]/runs/[runId]`** — ตารางเคสในรอบ: เส้นทางแม่แสดงเป็น
   หัวกลุ่ม (Scenario › Test Group) ไม่ใช่ทุกแถว, แต่ละแถวมีชื่อ + Priority +
   ผลของรอบนี้ (กดเปลี่ยนได้) + โน้ต; ปุ่ม "Add test cases" เปิด dialog ที่มี
   ตัวกรอง Module → Requirement → Scenario → Test Group แบบ cascade +
   Priority + ผลล่าสุด และเลือกทั้งกลุ่มได้
   verify: เพิ่ม 50+ เคสในครั้งเดียวแล้วจับเวลา query; บันทึกผลแล้วทั้ง
   `TestRunCase` และ `TestCase.testResult` ตรงกัน

6. **Verify รวม** — `tsc`, `eslint`, `npm test` (115 ต้องยังผ่าน + เทสต์ใหม่
   ของ lib รอบ), `npm run build`, ทุกหน้า 200 แล้วเก็บกวาดข้อมูลทดสอบ
