# My Work รอบสอง — Plan

Goal: หน้า My Work บอกได้ว่างานไหนกำลังจะสาย ไม่ใช่แค่สายไปแล้ว, เปลี่ยน
สถานะได้ในคลิกเดียว, และคนที่ไม่ใช่ Dev ก็ใช้มันได้

Current vs desired (Diff):
- ตอนนี้บอกแค่ `failed 2 times` → ต้องเห็นรูปร่างของความพัง (เคยผ่านแล้วพัง
  ใหม่ กับไม่เคยผ่านเลย เป็นคนละงาน)
- ตอนนี้เห็นสีแดงเฉพาะตอนสายไปแล้ว → ต้องเห็นเหลืองก่อนถึงกำหนด
- ตอนนี้เลยกำหนดแล้วเงียบ → ต้องเด้งที่กระดิ่ง
- ตอนนี้ต้องกด Save → กดสถานะแล้วบันทึกเลย
- ตอนนี้ Dev เท่านั้นที่ได้ประโยชน์ → ทุก Role เปิดดูงานของตัวเองได้

## ที่ผู้ใช้ตัดสินใจแล้ว

  แจ้งเตือนเกินกำหนด   เขียนตอนกระดิ่ง poll ไม่เพิ่ม scheduler
  Ready to retest     บังคับให้เขียนอธิบาย
  Filter              default เป็น "มอบหมายให้ฉัน" ทุก Role

## 1. Run history บนการ์ด

`RunHistoryList` เป็น server component ธรรมดา และหน้า My Work เรียก
`listRunHistoryForCases` อยู่แล้วเพื่อนับ `failed N times` — เอาแถบมาวางใน
ส่วนที่พับไว้ ไม่มี query เพิ่ม

## 2. เหลือเวลาเท่าไร และสีอะไร

สัดส่วน ไม่ใช่จำนวนวันตายตัว: Critical มีช่วง 1 วันทำการ ถ้าใช้ "เหลือ ≤2 วัน
= เหลือง" มันจะข้ามเหลืองทุกครั้ง

  เขียว   เหลือเกินครึ่งของช่วงที่ได้
  เหลือง  เหลือไม่เกินครึ่ง หรือเหลือ ≤1 วันทำการ
  แดง    เลยกำหนด

"ใช้เวลาไปกี่วันแล้ว" นับจาก `WorkEvent` ล่าสุดที่ `toState = ASSIGNED` ซึ่ง
การ์ดโหลดมาอยู่แล้ว (take 10) — ไม่ต้องเก็บวันเริ่มเป็นคอลัมน์ใหม่

## 3. แจ้งเตือนเกินกำหนด โดยไม่มีตัวรันตามเวลา

`/api/notifications/unread-count` ถูก browser ของทุกคนที่เปิดแอปยิงทุก ~30
วินาที เป็นสิ่งเดียวในระบบที่เดินเป็นจังหวะโดยไม่ต้องมี scheduler

  ทุกครั้งที่ถาม count → หา case ของคนที่ถาม ที่ `dueAt` ผ่านไปแล้ว
  และยังไม่เคยแจ้งสำหรับกำหนดส่งรอบนั้น → เขียนหนึ่งแถว

กันซ้ำด้วยการผูกกับ `dueAt` ของรอบนั้นเอง: หนึ่ง case หนึ่งกำหนดส่ง หนึ่ง
แจ้งเตือน งานที่เด้งกลับได้ `dueAt` ใหม่จึงแจ้งได้อีกครั้ง อย่างถูกต้อง

เขียนไว้ตรง ๆ ว่านี่คือการเขียนใน endpoint ที่ควรแค่อ่าน และคนที่ปิดแอปอยู่จะ
ไม่รู้จนกว่าจะเปิด — เป็นการแลกที่เลือกแล้ว ไม่ใช่สิ่งที่มองข้าม

## 4. กดแล้วบันทึกเลย

`InlineSelect` ทำแบบนี้อยู่แล้วและมี `needsNote` ที่เด้ง dialog ถามเมื่อเลือก
ค่าที่ไม่ควรบันทึกเงียบ ๆ — แต่มันเป็น dropdown ส่วนการ์ดใช้ปุ่มเรียงสามอัน
ซึ่งอ่านง่ายกว่าสำหรับค่าที่เป็นลำดับ

ทำ `WorkStatePicker` เป็น client component ใช้กลไกเดียวกัน (`requestSubmit`
+ dialog) แต่วาดเป็นปุ่มเรียง และบังคับโน้ตเฉพาะ `READY_TO_RETEST`

ต้องมี fallback เมื่อไม่มี JavaScript? ไม่ — `InlineSelect` ก็ไม่มี และหน้านี้
อยู่หลัง login ที่ต้องมี JS อยู่แล้ว

## 5. เมนู

  DEV        My Work มาก่อน Overview ไม่ได้ (ไม่มี Overview) — คงเดิม
  Role อื่น   "Assigned to me" อยู่ถัดจาก Overview

ชื่อที่ต่างกันเพราะความหมายต่างกัน: สำหรับ Dev มันคือรายการงานทั้งหมดของเขา
สำหรับ Tester มันคือเศษหนึ่งส่วนของงานโปรเจกต์ที่บังเอิญอยู่กับเขา

## 6. Filter

  มอบหมายให้ฉัน (default)   assigneeId = ฉัน
  ที่ฉันส่งต่อ                มี WorkEvent toState=ASSIGNED ที่ actor = ฉัน
  ทั้งโปรเจกต์               workState != null

default เป็น "มอบหมายให้ฉัน" ทุก Role เพราะชื่อหน้าบอกอย่างนั้น หน้าที่ชื่อ
ว่า My Work แล้วเปิดมาเจอของคนอื่นคือหน้าที่โกหกชื่อตัวเอง

## 7. Assign ที่หน้า Test Case

ตอนนี้แสดง `Assignee: developer 1` เป็นข้อความ — เปลี่ยนเป็น `InlineSelect`
ตัวเดียวกับที่หน้า Test Run ใช้ เรียก `assignCase` กั้นด้วย `EDITOR_ROLES`

Out of scope / do NOT touch (Fence):
- ไม่เพิ่ม scheduler / netlify.toml — ผู้ใช้เลือกวิธีกระดิ่งแล้ว
- ไม่แตะกติกาผลการทดสอบที่เพิ่งแก้ (`workOpsForResult`)
- ไม่แตะ production schema — ไม่มีขั้นไหนในแผนนี้ต้องแก้ schema เลย

Risks & unknowns:
- การเขียนใน route ที่ควรอ่านอย่างเดียว ต้อง idempotent จริง ๆ ไม่งั้นกระดิ่ง
  จะผลิตแถวทุก 30 วินาที — ต้องมีเทสต์ที่ยิงซ้ำแล้วยืนยันว่าได้แถวเดียว
- Filter "ทั้งโปรเจกต์" ให้ DEV เห็นงานของคนอื่นด้วย ซึ่งเป็นการอ่าน ไม่ใช่
  การเขียน และ VIEWER เห็นทุกอย่างอยู่แล้ว จึงไม่เปิดช่องอะไรใหม่
